# Design: Anglesite 1.1.0 Re-platform

**Date:** 2026-06-17
**Status:** Approved (design); pending implementation plan
**Branch:** `replatform/anglesite-1.1.0` (off `main`)

## Goal

Move `pulletsforever.com` from Anglesite `1.0.0-beta.6` onto the Anglesite `1.1.0`
foundation — a full re-platform — while preserving every current behavior and URL,
and additionally adopting the template's full Cloudflare worker + infrastructure to
gain inbound IndieWeb.

This is a "preserve everything, new rails" migration: the site behaves identically to
readers; only the foundation modernizes (plus new inbound-IndieWeb capability).

## Decisions (from brainstorming)

| Question | Decision |
|---|---|
| Custom features (feeds, llms.txt, content-negotiation, webmentions, JSON-LD) | **Preserve everything** — identical behavior, no URL changes, no feature loss |
| Output mode + Cloudflare infra | **Adopt full template worker + infra** — CF adapter, D1/R2/Queues, inbound IndieWeb (Micropub, webmention receiving) |
| Keystatic collections | **Posts only** — mirror the existing `content.config.ts` schema |
| Provisioning of D1/R2/Queues | **Claude provisions** against the owner's CF account after `wrangler login`, confirming each create |
| Cutover safety | **Preview deploy, then promote** — verify the full stack on a Cloudflare preview URL before production |
| Migration strategy | **Phased in-place migration in an isolated git worktree**, Astro 6 as a hard gate |

## Verified facts

- Template requires **Astro 6.3.1** (project is on 5.18.1) — a real major-version bump, the biggest risk.
- Template **still uses Markdoc** (`@astrojs/markdoc` 1.0.4, glob `**/*.{mdoc,mdx,md}`), so the 34 existing `.mdoc` posts load unchanged. The content pipeline is compatible.
- Template adds React (18.3.1) solely to host the Keystatic admin UI.

## Target architecture

- **Astro 6.3.1**, `@astrojs/markdoc` 1.0, **`output: 'static'` with the Cloudflare adapter** (hybrid):
  posts and pages stay statically pre-rendered (identical HTML/perf); only IndieWeb and
  `/keystatic` routes run on-demand in the worker.
- **Worker** moves `workers/site/` → `worker/`, built on the adapter. It absorbs the
  `Accept: text/markdown` → `index.md` content-negotiation and adds inbound-IndieWeb
  handlers (Micropub, webmention receiver, IndieAuth) backed by D1/R2/Queues.
- **Keystatic** (posts-only) over `src/content/posts/*.mdoc`, schema mirroring
  `content.config.ts` exactly. React added only for the `/keystatic` admin UI.
- **Tooling** upgraded to 1.1.0: modular `pre-deploy-check.ts` (+ `config.ts`, `csp.ts`,
  `seo.ts`, `seo-audit.ts`), `tsx` scripts, stylelint + markdownlint. Supersedes the interim
  hand-fix to the scan that currently lives on the PR #40 branch.

### Preserve-everything contract

Each surface stays behaviorally identical and gets an explicit verification step:

| Surface | Guarantee |
|---|---|
| Post URLs (`/<slug>/`) + content | Byte-comparable HTML before/after (diff static output) |
| Atom feed, JSON Feed, RSS | Same routes, same items, validated |
| `llms.txt`, `.well-known/*`, license, nodeinfo | Same routes/output |
| `Accept: text/markdown` → `index.md` | Same negotiation, re-homed in `worker/` |
| Outbound webmention + WebSub on deploy | Preserved in the new `deploy` script |
| JSON-LD / `site.config.ts` identity | Unchanged |
| Security headers / CSP / `_headers` / `_redirects` | Preserved; CSP reconciled with `csp.ts` |

## Phase plan

Each phase ends at a **gate** (build + typecheck + relevant tests green) before the next begins.

### Phase 1 — Astro 5→6 + Markdoc 1.0 (hard gate)
- Bump `astro` → 6.3.1, `@astrojs/markdoc` 0.14→1.0, and `@astrojs/sitemap`/`@astrojs/rss` to Astro-6 peers.
- Work through Astro 6 breaking changes against the config (`markdoc()` + `sitemap()`, glob loader, `astro:content` schema).
- **Capture a baseline first:** build on `main`, snapshot `dist/**/*.html` as the regression oracle.
- **Gate:** all 34 posts build, `astro check` clean, every endpoint (Atom/JSON/RSS, `llms.txt`, `.well-known`, `index.md`) renders, HTML diff shows only intended changes. Explicit feed-render test (feeds render HTML via `@markdoc/markdoc` directly — the most likely API shift).

### Phase 2 — 1.1.0 tooling (supersedes the hand-fix)
- Copy `scripts/config.ts`, `csp.ts`, `seo.ts`, `seo-audit.ts`; replace `pre-deploy-check.ts` with the 1.1.0 version.
- Reconcile config: keep `PII_EMAIL_ALLOW` for the fediverse handles; drop the `user@domain.com` entry (RFC 2606 reserved-domain handling covers it); let `csp.ts buildAllowedScripts` cover `/js/footnote-popup.js` via `.site-config` instead of a hardcoded allowlist.
- Add `stylelint` + `markdownlint-cli2` configs; convert custom scripts (`new-post`, `send-webmentions`, `ping-websub`) to `tsx`.
- **Gate:** `npm run predeploy` passes on the Phase-1 build; lints run.

### Phase 3 — Keystatic (posts-only) + React
- Add `@keystatic/astro`, `@keystatic/core`, `@astrojs/react`, `react`, `react-dom`.
- `keystatic.config.ts`: single `posts` collection whose fields mirror `content.config.ts` exactly
  (`title, description, publishDate, image, imageAlt, tags, draft, syndication`); storage local, format markdoc, path `src/content/posts/*`.
- `anglesite.config.json` declaring the collection; wire `react()` + `keystatic()` in `astro.config`.
- **Gate:** an existing post opens in the editor and round-trips to identical `.mdoc` frontmatter; posts still prerender static. (`/keystatic` on-demand route fully validated once Phase 4's adapter lands; until then validate via `keystatic` local dev.)

### Phase 4 — Worker restructure + CF adapter
- Add `@astrojs/cloudflare`; `output: 'static'` with on-demand only for IndieWeb/`/keystatic` routes (everything else prerendered). Convert `wrangler.toml` → `wrangler.jsonc` (assets binding + adapter).
- Move `workers/site/index.ts` → `worker/`, porting the `Accept: text/markdown` → `index.md` negotiation; keep `[slug]/index.md.ts` generating the markdown variants. Port worker tests to the new path.
- **Gate:** `wrangler dev` serves pages + content-negotiation; worker tests pass; `wrangler deploy --dry-run` clean.

### Phase 5 — Infra + inbound IndieWeb (Claude provisions)
- After `wrangler login`: run `wrangler d1 create` (auth/micropub/webmention), `wrangler r2 bucket create`, `wrangler queues create` — confirming each — and wire returned IDs into `wrangler.jsonc`. Apply D1 schema/migrations (read exact schema from the template at this phase).
- Add the template's Micropub / webmention-receiver / IndieAuth handlers wired to bindings; extend `.well-known`/`site.config.ts` to advertise the new endpoints (keep existing).
- **Gate:** endpoints respond under `wrangler dev` with local D1; a self-test webmention round-trips to D1.

### Phase 6 — Preview deploy → promote → docs
- Deploy to a Cloudflare **preview** URL (`wrangler versions upload` or a `*-preview` worker name); verify the full stack there (pages, feeds, `llms.txt`, content-negotiation, `/keystatic`, IndieWeb). Diff against prod for regressions.
- **Promote** only when green (`wrangler versions deploy` / `wrangler deploy`) — custom domain/routes unchanged, no DNS changes. Post-promote: run outbound webmention/WebSub, smoke-test prod.
- Update `CLAUDE.md` (Astro 6, `worker/` path, new commands/infra) and `.site-config` (`ANGLESITE_VERSION=1.1.0`, refreshed `AI_MODEL`, plus only new keys actually consumed by the code).

**Dependency note:** Phases are strictly ordered — Phases 3 and 5 both depend on the Phase-4 adapter for their on-demand routes, so the Keystatic UI and IndieWeb get fully validated only once the worker lands.

## Testing strategy

Standing gate every phase must pass:
- `npm run build` (all 34 posts + endpoints), `astro check`, worker tests, `npm run predeploy`, lints.
- **HTML baseline diff** — the Phase-1 `dist/` snapshot is the regression oracle; diff after each phase, explain every delta.
- **Endpoint contract checks** — Atom/JSON/RSS validate; `llms.txt`/`.well-known` byte-stable; `curl -H 'Accept: text/markdown'` returns the `index.md`.
- **Feature-specific:** Keystatic round-trips a post to identical frontmatter (Phase 3); a self-sent webmention persists to D1 (Phase 5).

## Cutover mechanics (preview → promote)

1. `wrangler versions upload` (or a `--name pulletsforever-preview` worker) → a Cloudflare preview URL exercising the real adapter + real D1/R2/Queues, with zero production traffic.
2. Run the full endpoint + IndieWeb + `/keystatic` checklist against the preview URL; diff key pages against live prod.
3. Promote only when green (`wrangler versions deploy` / `wrangler deploy`). Custom domain and routes unchanged — promoting swaps the worker version, no DNS changes.
4. Post-promote: run outbound webmention/WebSub, smoke-test prod.

## Risks & rollback

| Risk | Mitigation |
|---|---|
| Astro 5→6 breaking changes (biggest) | Phase-1 hard gate + HTML baseline diff. If it spirals, fall back to shipping Astro 6 as a standalone PR and pause the rest. |
| Markdoc 0.14→1.0 in `feed.ts` (feeds render HTML via `@markdoc/markdoc` directly) | Explicit feed-render test in Phase 1; most likely API to shift. |
| CSP reconciliation (`csp.ts` vs existing `_headers`) | Diff generated CSP against current `_headers`; preserve directives, fail the gate on drift. |
| Billable/irreversible infra | Confirm each `create`; D1/R2/Queues have free tiers; resources namespaced to avoid collisions. |
| Bad promote breaks prod | Worktree keeps prod untouched until promote; promote is a worker version swap → `wrangler rollback` (or redeploy prior version) reverts in seconds. Old `workers/site` stays deployable until confident. |

## Open items (resolved during implementation, not now)

- Precise D1 schema the template's IndieWeb handlers expect — read from the template at Phase 5.

## Out of scope

- The 9 new optional feature skills (membership, podcast, consent, giscus, inbox, donations, redirects, export, forms) — opt-in, can be invoked later after `/reload-plugins`.
- Any post-content changes (the handwriting post and PR #40 are independent work).

## Relationship to other work

- PR #40 (blog post + interim scan hand-fix) is independent. Phase 2 replaces the scan files wholesale, so it supersedes the hand-fix cleanly whether or not #40 has merged first.

## Execution note

This is large enough that the implementation will likely become a short sequence of plans
(e.g., Phases 1–2, then 3–4, then 5–6) rather than one monolith — each verified before the next.
